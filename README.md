# RenpyTranslatorNG

Ren'Py 8.x 游戏可视化汉化工具。老版 RenpyTranslator 在 Ren'Py 8 上失效后的重写版：
纯官方 tl 挂载方案 + LLM 翻译 + 人物关系约束 + 现代 GUI。

## 启动

双击 **`RenpyTranslatorNG.lnk`**（带图标，推荐）或 `启动.bat`。两者均以 `pythonw` 启动，
**不会弹出终端窗口**；日志全部显示在 GUI 的「进度 / 日志」面板中，未捕获异常会弹窗提示。
命令行调试可用 `py -X utf8 run.py`（带控制台，便于看原始报错）。
依赖：Python 3.10+，`pip install PySide6 requests`。

## 开发：安装依赖与运行测试（一条命令）

干净机器上（Python 3.10+ 已装）：

```bat
pip install -r requirements-dev.txt && pytest
```

- `requirements.txt` / `requirements-dev.txt` 按版本锁定依赖，重复安装得到相同版本。
- 测试套件全部使用临时目录，不引用本机绝对路径或真实游戏目录，统一退出码由 pytest 给出。
- 只跑界面（不跑测试）的环境装 `requirements.txt`（含 PySide6）即可。
- 私有回归（引用开发者本机真实游戏样本、受版权保护不入库）默认跳过；
  设 `NG_PRIVATE_REGRESSION=1` 后 `pytest tests/test_ipatch.py` 才会执行该部分。

界面默认为深色主题，右上角 **🌙/☀** 按钮可在深色 / 浅色之间一键切换；
按钮固定在页面顶端不随页面切换消失，选择保存在 `config.json` 的 `theme` 字段，下次启动沿用。

## 使用流程（GUI 内按顺序点）

1. **① 解包资源** — 纯 Python 解开 `.rpa`（自动跳过已解出的文件）
2. **② 反编译脚本** — 用内置 unrpyc 把 `rpyc → rpy`，**只处理 game/ 目录**，
   并自动清理 `renpy/common` 里的反编译残留（残留会与引擎 `_ren.py` 冲突导致游戏无法启动，
   这正是老工具在 Ren'Py 8 上坏掉的原因）
3. **③ 提取+生成tl** — 注入一次性钩子运行游戏几秒钟，导出对白元数据并用
   **官方翻译生成机制**产出 `game/tl/<语言>/` 空骨架（只含对白与必要 UI 串，避免 tl 膨胀导致的卡顿）。
   游戏带 **ipatch 台词补丁**时，此步自动解析补丁并把补丁内容覆盖到翻译源
   （详见下文「ipatch 台词补丁覆盖」）。
   随后自动执行 **Python 字面量补提取**：扫描反编译源码，把官方机制看不到的数据驱动文本
   （`init python` 里的 `add_action("...")`、`Location("...")`、动态菜单标题、变量对白列表、
   自定义语句参数等）写入 `tl/<语言>/zz_ng_pystrings.rpy` 补充骨架，并生成
   `game/zz_ng_dyntrans.rpy` 运行时过滤器（`_ng_t()` 安全查表 + `config.say_menu_text_filter`
   让变量对白/动态菜单也过译文表）。配合反编译阶段的显示端包装（字面量包 `_()` 供官方提取，
   表达式/变量包 `_ng_t()`，查不到译文时原样返回、零副作用）。**补骨架只追加新条目，
   重复执行绝不改写已有内容；已译条目自动跳过、绝不重复计费。**
4. **④ AI关系草表** — 调用模型分析各角色抽样台词，推断人名/性别/长幼关系
   （扫描固定用低温度 0.3 输出 JSON；单批失败自动重试，重试耗尽则跳过该批继续，
   部分结果照常保存，缺的角色可在③页手动补；全部批次失败时不动原有关系表），
   一键全流程到这里会弹窗把整张关系表摆出来核对，双击单元格即可就地修改，
   改动在关闭弹窗时存盘、紧接着的翻译直接采用（不必中断流程再去改页表）；
   也可以随时到「③ 人物关系」页审核修改（解决 sister/brother 忽姐忽妹的问题）。
   扫描**全部**说话人（不设数量上限；游戏脚本里 `define xx = Character("Name")`
   的真实人名会注入提示词，AI 只译名不再猜名），样本过大时自动分批请求
5. **⑤ 翻译并回填** — 批量调用 OpenAI 兼容 API（DeepSeek/OpenAI/Ollama/LM Studio…），
   词汇表与人物关系注入提示词；断点续翻，译文写回 tl 文件
6. **⑥ 字体+语言入口** — 中文字体以 `translate <lang> python:` 覆盖（切回英文自动还原原字体）；
   游戏左上角「中文/EN」切换按钮，启动自动恢复上次语言

### 省钱试玩 / 断点续翻

- **⏸ 暂停**：翻译中随时点「暂停」，已完成批次实时保存；再次执行第 5 步从剩余部分继续，
  已译内容不会重复请求（「统计工作量」会显示 已译/待译）。
- **↻ 重译未译句子**：翻译失败重试的省钱模式——只把缓存里没有译文的句子重新发给 AI
  （已译内容绝不重复请求，每句至多附前后各 1 句上下文），反复执行可逐步清零失败句。
- **⤵ 回填已译部分（试玩模式）**：不调用 API，把当前已有译文写入 tl 并应用字体/语言入口，
  未译行显示英文——先试玩翻译了一部分的游戏，再决定是否花钱翻完全部。
- 设置页「模型」框旁有 **⟳ 拉取模型**：填好接口地址和 Key 点一下即拉取模型列表，不必手填；
  旁边的 **✓** 按钮只校验手动填写的单个模型（不拉全表，OpenRouter 会显示上下文长度与价格，
  免费模型标“免费”）。
- 设置页顶部 **已存接口**：点「存为方案」把当前的接口地址、API Key、模型，以及
  温度 / 重复惩罚 / 思考模式 / 并发数 / 每请求行数 / 超时 / 单次回复上限 / 输入预算 /
  System Prompt 等**全部参数**存成一个方案；之后在下拉框里选中即整份还原，
  在 DeepSeek 官方 / OpenRouter / 本地 LM Studio 之间切换不用再逐项重调。
- 设置页 **单次回复上限**（`max_tokens`）、**输入预算**（估算 token）：本地模型必填。
  不设上限时模型可以一直复读写到上下文窗口用满，推理服务会直接报
  `Context size has been exceeded` 并掐断同批所有并发请求（表现为进度条长时间不动、
  反复重试后失败）。填法：`输入预算 + 单次回复上限` 小于模型的上下文长度，
  例如 LM Studio 里上下文设 16k，则输入预算 6000~8000、单次回复上限 2048。
  在线 API 两项都保持 0 即可（不发送参数，行为与以前完全一致）。
- 批次容错：输入超预算或撞上上下文上限时**自动对半拆小重试**（而不是原样重发）；
  回复被输出上限截断时会保留已解析出的条目、只补译剩下的；连续 20 个批次整批失败
  会中止本轮并给出排查提示（本地模型/服务端坏掉时不再空转几小时）。
  译文缓存改为按时间/批次节流落盘，长任务不再被整份重写拖慢。
- 设置页 **思考模式**：DeepSeek V4 系列（v4-flash / v4-pro）默认开启思考模式（强度 high），
  思考内容按输出 token 计费——翻译这类结构化任务选「关闭思考」可大幅省钱；
  「开启·低/高强度」按官方格式发送 `thinking` + `reasoning_effort`（思考模式下温度/惩罚参数会被官方忽略）；
  「跟随服务商默认」不发送该参数，兼容 OpenAI / Ollama 等不认识此字段的服务端。
- 数值设置（温度 / 并发数 / 每请求行数等）均为 **直接键入** 的填写框：没有步进箭头、
  不响应鼠标滚轮，鼠标划过不会再误改数值。
- 设置页 **AI 角色提示词**：内置翻译 System Prompt 直接可见、可改（`{lang}` 占位符代表目标语言；
  人名对照/词汇表/人物关系仍自动附加），「恢复默认」一键还原。

### 「🎮 游戏库」页：游戏图鉴墙

- **扫描入库**：可指定任意文件夹或整个磁盘/分区递归扫描（最多 5 层，自动跳过系统目录），
  发现 Ren'Py 游戏自动入库；也可「＋ 添加游戏」手动选择目录加入。
  扫描在后台执行，可随时「⏸ 暂停」。
- **自动判定汉化状态**：入库时检查游戏的 `game/tl/` 下是否存在 Chinese / 中文 / 简中 / 繁中 / 汉化
  语言目录，分成「✅ 已翻译」与「🌐 未翻译」两个分区展示（重新扫描会刷新状态）。
- **卡片操作**：点击封面弹出菜单——**▶ 启动游戏**（自动挑选主程序 exe，多启动器时选对主程序）、
  **🖼 更换封面**（选一张本地图片，复制到工具 `covers/` 目录保存）、
  **🌐 网络找封面**（联网按游戏名搜一遍并覆盖当前封面）、
  **⭐ 获取评分 / 🔄 刷新评分**（见下）、
  **📂 打开游戏目录**、**🎯 设为当前项目**（回填到①页的游戏根目录，直接开始翻译流程）、
  **🗑 从库中移除**（只删记录，不动游戏文件）。
- **游戏评分**：卡片上游戏名下方显示五星评分条 + 分数 + 评分人数，鼠标悬停看完整来源。
  点「⭐ 更新评分」批量查询（已抓过的跳过，F95 的满 30 天、dikgames 兜底的满 3 天才重抓；
  全部都有评分时会问是否全部重抓），也可右键单张卡片刷新（「🔄 刷新评分」）。
  两个数据源都无需登录，**F95Zone 优先，没收录的换 dikgames**：
  - **F95Zone**（5 星制）：用官方 JSON 检索接口按名字搜到帖子，再读帖子页 JSON-LD 里的
    `aggregateRating`，拿到精确到两位小数的评分与准确的投票人数；
  - **dikgames**（10 分制）：站内搜索找到帖子页，同时取两套评分——**站点评分**（带 Great / Fair
    这类评语）与**用户平均分 + 投票人数**；卡片上显示用户均分，站点评分在悬停提示里。
  名字匹配从严（完全一致 → 标题是游戏名的扩写 → 标题是游戏名开头、后面是版本尾巴），
  查不到宁可不显示，也不乱配；搜索词会自动去掉 `a/and/with` 这类虚词与逐级截短——
  F95 的检索对多词串很挑剔，`No More Money` 要退到 `More Money` 才搜得到。
  F95 对匿名请求按小时限流：请求之间自动留间隔，被限流先退避重试，仍是 429 就冷却 10 分钟、
  本批改用 dikgames（纯 5 星制那条下次更新时再补，不会丢）；线程页不受该限流影响，命中后取人数照常。
  **想解除限流**：设置页「F95 登录 Cookie」填自己账号的 Cookie（F12 → 网络 → 任意请求 →
  请求头里的 Cookie 一行，整行粘贴）即可；只存在本机 `config.json`，只发给 f95zone.to。
- **新版本检查（启动后台静默查）**：打开程序约 1.5 秒后自动在后台比对本机游戏与线上最新版本，
  **全程静默**——不锁界面、不弹窗、不挡操作，也不打断你手上的活
  （侧栏状态灯显示「检查更新 12/114」的进度，你照常翻页 / 翻译 / 扫描）；
  **没有新版本时什么都不显示**，确认有新版本才在封面左上角标一个紫色「可更新」，
  鼠标悬停看「线上 v0.21.4（F95Zone）｜本地 0.18.3」，
  顶栏会出现「🔄 可更新 N」计数，筛选框选「🔄 可更新」只看这些游戏；
  点卡片 →「⬆ 打开更新页」直接开 F95 帖子，「🔍 检查更新」单独重查一个。
  想关掉启动检查可在设置页取消「启动时后台静默检查游戏库更新」，关掉后仍可用顶栏
  「🔍 检查更新」手动补查（都刚查过时会问是否整库重查）；
  右上角「版本信息：3 小时前检查」告诉你现有角标是什么时候的数据。
  注意**评分**不同：评分只在点「⭐ 更新评分」时联网，不做启动自动检查。
  - **本地版本从三处取证**：`log.txt` 头部（Ren'Py 8.2+ 会写下 `config.name` / `config.version`）、
    `game/options.rpy` 的 `config.version`、以及游戏**目录名**（下载包名基本都带版本尾巴，
    取「去掉游戏名之后」的部分，免得把 LabRats2 / TFTUV2 这类名字里的数字当版本号）。
  - **线上版本**：F95Zone 检索接口的 `version` 字段（如 `v0.09 v4 Fix`），没收录的退回
    dikgames 搜索结果标题的 `[v1.0]`；与评分共用同一套请求节流与代理/直连切换。
  - **判定从严**（只比数字）：主版本号（带小数点的那个）优先，再比修订号；
    `S4` / `Ep.4` / `Part2` 这类「第几季第几集」的内容标记不算修订号
    （否则线上的 `v4.4.3 S4 Ep.4 Gold` 会被误判成比本地的 `4.4.3` 新），
    `Supporter` / `Fix` / `market` / `Beta` 这类词也不参与比较。
    只有**线上版本严格高于本地所有候选版本**才提示，其余（本地版本更新、两站都没收录、
    目录名里读不到版本号）一律不标——宁可漏报，也不让你白下一遍几十 GB 的重复包。
  - 同一游戏 12 小时内只查一次（所以启动检查只补查过期的，正常用下来每次启动很快结束，
    F95 的每小时额度也留给评分查询）；上次被限流没查全的过几小时补一次，
    两个站都没收录的隔几天再看；检查时若你发起了翻译/扫描/评分等正式任务，
    它会立刻让出网络与 `library.json` 的写入权、等任务结束再接着查（关窗口也会立刻收尾）。
    版本结果写在 `library.json` 每个条目的 `update` 字段里，所以角标不联网也在，
    重新打开程序时旧结果照常显示。
  - 已知局限：只比数字，不看发布说明。**作者中途换版本号写法**的游戏
    （如 `0.03` → `Ch.3`）会被当成新版提示；名字连写成一串全大写、或站点根本没收录的
    游戏搜不到就是搜不到（和「⭐ 更新评分」同一套名字匹配，那里没有评分的就是这类）。
    判不准的一律不标，卡片悬停提示里会写清「线上 …｜本地 …」让你自己判断，
    点「⬆ 打开更新页」可去站点核对。
- **自动找封面**：扫描/刷新时先在游戏根目录找现成封面图（`cover` / `poster` / `banner` / `title` /
  `icon` / `logo` 整名优先，也认 `cover1.png`、`game_cover.jpg` 这类变体）；
  本地没有的按游戏名联网搜索同名游戏抓取封面，按顺序尝试多个源、先命中先用：
  **VNDB**（视觉小说数据库，开放 API 免密钥，竖版盒图）→ **dikgames**（无需登录，国内可直连，横幅图）。
  匹配从严：标题与游戏名一致优先、包含匹配次之，匹配不上宁可保留占位图也不乱配
  （可随时「⏸ 暂停」）；请求系统代理失败自动切直连重试，某个源被墙/故障时自动冷却并改用其他源。
  下载的封面缓存在工具 `covers/` 目录（F95Zone 的图是横幅位图，只当评分源用，不当封面源）。
- 无封面的游戏显示按游戏名生成的渐变占位封面。
- 游戏库数据保存在工具根目录 `library.json`，与游戏文件互不影响。

### 「③ 人物关系」页：关系表 + 关系词显示表

- **人物关系表**：每个角色的说话人代号 / 人名 / 中文名 / 性别 / 与主角关系（含长幼）/ 备注，
  翻译时注入提示词，决定「姐姐/妹妹/哥哥/弟弟」这类称谓的一致性。
- **关系词显示表**（下半页）：给「开场让玩家自己填关系词」的游戏收尾。
  这类游戏（如 The Home of Pleasure）用 `renpy.input` 问「那你是她的……」，玩家填的词
  存进变量、以 `[relation2]` 形式插值进台词——**译文管不到它**，游戏里就会冒出
  「你是我的brother」。在表里填一行 `brother → 弟弟`，台词即按你的设定显示：
  - 复数自动加「们」（原文 `[relation1]s` → `姐姐们`），所有格自动加「的」→ `姐姐的`；
  - 玩家在游戏里**直接输入中文**（如「弟弟」）时以他当场的输入为准，工具自动把它转成
    `brother` 交给游戏逻辑（游戏里的 `!= "friend"` 这类判断照旧）；
  - 同一个英文词被**两处提问**问到、而玩家两次答得不一样时（The Home of Pleasure 就是：
    「苏菲是你的…」和「格蕾丝是苏菲的…」英文都是 `sister`），显示层分不清某句台词属于哪一处，
    这份回答一律作废、按本表显示——否则「最后一次输入」会通吃所有同词台词
    （给苏菲填了妹妹、格蕾丝那处填了姐姐，连「你把手机拿给妹妹们看」都变成「姐姐们」）；
    两处答得一致时仍以玩家的词为准；
  - 玩家输入英文时优先按本表，其次按提问语境（`younger/older`）判断长幼；
  - 表留空则用内置默认（brother→哥哥、sister→姐姐…），「填入常用关系词」一键铺开再改长幼；
  - 改过这张表之后，玩家此前在游戏里的输入记忆会整体作废（否则旧的长幼会一直盖住新设定），
    表没变时玩家的输入照旧保留。
  保存后执行第 6 步（或「④ 译文修改」页的「应用修改到游戏」）生效，只改显示层，不动 tl。

### 「④ 译文修改」页：不重译的善后手段

- **关键词搜索 + 高亮**：搜译文/原文，命中的台词列表高亮关键词；双击「译文」列可单条修改。
- **一键替换**：如人物关系理解错了，导致台词忽而「哥哥」忽而「弟弟」——搜「哥哥」，
  替换框填「弟弟」，一键全部替换（或只双击改个别几条），再点「应用修改到游戏」回填生效，
  全程不调用 API、不重新翻译。
- **🔧 修复标签错乱**：修复译文缓存里 `{/i}` 被写成开标签、`{ i }` 带空格等问题
  （游戏里显示 `/i` 乱码的根治手段）。新翻译会在入库时自动修复。

## ipatch 台词补丁覆盖

很多游戏带着 F95 社区的 `*_ipatch.rpy` 台词补丁（关系改写：把 Roommate/Landlady 改成
Sister/Mother；台词还原：整句换掉被和谐的原句）。补丁是**运行期生效**的——不改 rpyc，
游戏脚本里仍是旧文本，直接翻译"旧文本"会导致中文全是没打补丁的内容。

本工具在**提取阶段**就解析补丁（`core/ipatch.py`，第 3 步自动执行，日志会列出识别结果），
把补丁内容覆盖到翻译源上：

- **文本替换链**（`text.replace("旧","新")`，UNIVERSAL_ipatch / Double_Perception 等）：
  按补丁原始顺序逐条应用到提取出的原文上，AI 拿到的是打完补丁的台词；
- **伪语言整句改写**（AnotherChance 的 `translate ipatch <节点>:`）：该节点直接采用补丁
  作者的最终文本作为翻译源；
- **补丁自有文本**（StrongDesire 类补丁换掉的输入提示词 "(default is Sister)."）：游戏源码里
  不存在这些字面量，工具把它们收进 strings 骨架一起翻译，并在运行时给 `renpy.input`
  套一层译文表包装（包装在补丁的猴子补丁内侧，补丁替换出的新提示词同样被翻译）；
- **变量改写**（Crossworlds 的 `$ Landlady = "Mother"`）与说话人改名
  （`Character_x.default_name`）：解析并记录到工作目录 `ipatch.json` 供排查；
- **整句映射字典**（猴子补丁 `renpy.exports.say` + `replacements = {"原文": "补丁后"}`
  的关系补丁，文件名常是 `patch.rpy`）：按**整句精确匹配**覆盖翻译源（字典条目之间
  大量互为子串，绝不能走 replace 链）。这类补丁不看说话人，作者把 `"[mname]…"`
  映射成 `"son…"` 时，女友/路人说同一句也会变成「儿子」——这类误伤写进
  `work/<游戏>/ipatch_skip.json`（数组，元素是块标识符或 `块id:s1` 形式）即可人工排除，
  被排除的条目按游戏原文翻译。

安全性设计：译文仍按**原文**写回 tl（对白运行期按节点标识符查表、与文本无关，strings
条目的 `old` 一律不动），所以游戏内查表绝不会因覆盖而失效；tl 骨架与提取结果不动，
覆盖只发生在构建翻译任务时。补丁文件自身被排除在一切文本提取扫描之外。

回填是**按任务 key 精确写入**的：同一句英文在不同分支可以保留各自的既有译法（不会被
"同句同译"抹平），被人工排除补丁的条目也保住自己的译文；只有从没译过的同句才复用同一
译文（省一次请求）。

补丁增删/换版本后再执行第 5 步：受影响条目（源文本被补丁改过的）自动作废重译，
未受影响的照常断点续翻。**已翻译过的游戏**补上补丁后重跑第 5 步，只有被补丁改写的
句子会重新计费。已知局限：变量值经 `[插值]` 显示的中文要靠「译文修改」页手工润色；
补丁里依说话人不同的条件替换（Double Perception 的 `[c_r.name]` 按说话人分支）按全局
替换处理。

## 说明

- 翻译出错/漏译的行在 tl 中保持空串显示原文，不会破坏游戏；重跑第 5 步即续翻。
- 模型输出中错乱的 Ren'Py 标签（`{/i}` 当 `{i}` 用等）会在入库和回填时自动修复；
  旧缓存可用「④ 译文修改 → 修复标签错乱」一键修复。
- **文本标签校验（`core/texttags.py`）**：引擎渲染只认 `{tag}` 与 `{tag=value}` 两种写法
  （`renpy/text/text.py` 里是 `tag, _, value = text.partition("=")`），写成 `{image:x}`
  时整串会落到 `Unknown text tag` 分支**直接抛异常**；而引擎自带 lint 会把 `:` 也当参数
  分隔符剥掉，所以这种笔误能过 lint、只在运行时炸。因此入库/回填时会自动把
  `{image:x}` 改写成 `{image=x}`（只改 `image/color/size/font/a/cps/k/space/vspace/…`
  这类必须用 `=` 的标签；`{axis:x=1}` 与 `{#rrggbb}` 是引擎确实用冒号的写法，不动），
  缓存里改不掉的写法（未知标签名等）在「修复标签错乱」时单独列出。
  逐条复核用 `work/_rtl_run.py tagcheck`（见下一节）。
- **变量校验（`core/texttags.py::fix_interps`）**：`[变量]` 插值按 Python 标识符从 store
  取值（`renpy/substitutions.py`：`SIMPLE_NAME` 不匹配或不在 scope 里就走 `py_eval`），
  **大小写与下划线都算数**——原文 `[PlayerName]` 被模型"规范化"成 `[player_name]` 就是
  运行时 NameError，整段对白直接崩（2026-09-17 The Home of Pleasure 全游戏 198 处，
  走到哪句崩哪句，`log.txt` 里一晚撞了两次）。所以：入库时按原文逐字符还原变量名
  （只改名字，`[var!t]` 的转换后缀保留）；回填时**译文里多出原文没有的变量就整条拒用**
  （这些行显示英文原文并留在缓存里，重跑第 5 步会重译，日志会逐条列出）。
  提示词也不再举 `[player_name]` 这类具体变量名当例子——模型会把示例名抄到别的变量上
  （实测把原文的 `[mc_name]` 写成了 `[player_name]`），只留"逐字符照抄"的硬规则。
  译文里"整句串到隔壁行"（每格装着上一句的中文）也见过，那种错位不崩但显示的是别的台词，
  变量审计能顺带发现：`work/_audit_interp.py`、单游戏修复参照 `work/_fix_thp.py`。
- 人名映射以游戏脚本 `define xx = Character("Name")` 解析出的**真实人名**为键，
  AI 关系表的人名只有在与真实人名指向同一角色时才采用（防止 AI 猜错导致张冠李戴）；
  Guard/Tavernkeep 等龙套用内置词典翻译，不确定的名字保持英文。
- **关系词/人名替换在显示层做**（`zz_ng_text.rpy` 的 `config.replace_text`），所以
  变量插值出来的英文词也能汉化。词边界**不能用 `\b`**：汉字在 Python 正则里也算 `\w`，
  「你是我的brother」里 brother 前后都没有 `\b`，整句英文词会原样漏出去——必须用
  ASCII 前后视断言。同一条替换顺带吃掉复数/所有格的 `s / 's`，渲染成「们 / 的」。
- 显示层的运行期映射表/正则**放在普通 Python 模块（`sys.modules`）里，不要放 store**：
  store 变量会被写进存档、也会随回滚还原，读旧档时带回来的映射是按**当时的关系词表**
  算的，会盖掉 init 按当前表算出的结果——症状是改完关系词表、读旧档或回滚一下，
  台词里又是旧称呼（sister 又变回姐姐）。模块对象既不进存档也不参与回滚。
  回归测试见 `tests/test_ng_textmap.py` 的 Part 7。
- 想还原游戏：删除 `game/zz_ng_language.rpy`、`game/zz_ng_text.rpy`、`game/tl/<语言>/`、`game/fonts/` 即可。
- Ren'Py 引擎升级后只需更新 `vendor/` 下的 unrpyc。

## 交付前自检（改完 tl 必跑）

1. `./<游戏>.exe . compile` —— 全量重编译。**改过 tl 的 .rpy 一定要跑**：Ren'Py 按
   ".rpyc 末尾 16 字节 = 源码 md5" 判断是否需要重编译，只要两者对得上就直接加载 .rpyc，
   .rpy 改了而编译产物没跟上时，游戏跑的还是旧文本。
2. `work/_rtl_run.py structure` —— tl 结构完整性（strings 块 old/new 配对）。
3. `work/_rtl_run.py tagcheck` —— 文本标签体检：**崩溃风险**（未知标签名、用 `:` 传参、
   **译文多出原文没有的 `[变量]`**）、「译文 == 原文」行上的同类写法（市场自带、不渲染即无害）、
   以及译文相对原文**缺失**的 `{tag}` 与 `[变量]`（关系补丁把 `[mname]` 换成具体称谓属预期，
   单独计数）。
4. `work/_audit_interp.py <游戏根目录>` —— `[变量]` 专项审计（大小写被改、名字被换、
   变量被整个翻译掉），跨游戏可用；工具回填时已自动拦这一层，这里是复查与修旧文件用。
5. `work/_rtl_run.py verify` / `strcheck` —— 逐行分类与已有译文是否被动过。
