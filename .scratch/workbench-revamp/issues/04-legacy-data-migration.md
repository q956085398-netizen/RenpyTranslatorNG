# 04: 旧数据自动迁移

**What to build:** 升级首次启动时扫描现有 work/ 目录下的各项目 JSON 数据、游戏库记录文件与应用配置,生成迁移预览和备份,确认后导入注册库与项目存储。迁移幂等,可重复执行而不产生重复数据;无法可靠匹配的内容进入待检查项而非静默丢弃。用户近百条游戏库记录与已付费译文一条不丢。

**Blocked by:** 03(项目注册库与稳定项目身份)

**Status:** resolved

- [x] 迁移前展示预览,自动创建备份,失败可从备份恢复
- [x] 迁移前后项目数量、译文数量、人工修改内容可对账(对账率 100%)
- [x] 重复执行迁移不创建重复项目或重复译文记录(幂等测试)
- [x] 无法可靠匹配的内容成为待检查项,带有来源说明
- [x] 游戏库记录与应用配置保留并可在新结构中正常使用

## Answer

实现（ADR-0001、ADR-0004；测试 `tests/test_migration.py` 17 项；code-review
双轴处理后落地）：

- **扫描与匹配**：`core/migration.py` 的 `scan()`（只读）——发现 work/ 下含
  旧数据文件的目录（跳过备份目录、下划线开头的内部目录、已按项目身份存放
  的新式目录），按目录名在 library.json 游戏条目 + config 的 last_game 里
  匹配游戏安装（basename 大小写不敏感、候选去重）：唯一 → new/merge（后者
  是已登记项目）、无 → missing、多个 → ambiguous（绝不猜）。
- **预览与执行**：启动后后台扫描，**有可迁移项目才弹预览**（已迁移/暂不可
  迁移的静默跳过，绝不每次启动骚扰）；确认后在 Worker 里执行 `apply()`。
  对账报告：项目 新建/并入/跳过，译文 导入/保留/待检查，`reconciled` 断言
  四类之和 == 总数（测试断言 6 = 4+2）。待检查项带 key/内容/来源文件/说明，
  逐条写入「① 流程」页任务摘要。
- **备份与恢复**：任何导入发生前自动创建 `work/_migration_backup/<时间戳>/`
  （旧项目目录整目录 + library.json + config.json + manifest.json），测试在
  backup/assets/occurrences/translations/marker/finish 六个阶段注入失败，均
  回滚到迁移前状态（新建项目删除登记、项目资产目录按迁移前快照还原、标记
  撤掉，无半应用）。恢复入口：设置 → 数据维护「从迁移备份恢复…」
  （`restore_backup()` 复制回原位，不删备份之外的新文件）。
- **导入语义**：并入已登记项目时绝不覆盖新数据——出现位置已存在且结构指纹
  与旧数据不一致的旧译文按 ADR-0001 保留为**迁移建议**（source=migration，
  `record_migration_suggestions` 新入口，采用经 adopt_candidate）；出现位置
  已消失的进待检查项。全新/空项目以旧 dump+jobs 打底同步出现位置（对白
  src_file 从 dump 取，与新提取同构——测试验证迁移后真实提取再同步
  **零降级**），译文经 `import_currents(source="migration")` 只补空位。
  项目资产文件拷贝只补缺不覆盖，被让位的进待检查项。
- **幂等**：旧目录写 `_migrated.json` 标记（数据原样保留）；标记在 → 整项目
  跳过；标记丢失（崩溃后）重跑走并入路径只补空位。两条路径都有测试。
- **任务协调**：每个项目的导入作为项目任务（kind=migrate）经协调器
  `begin()` 原子登记（BEGIN IMMEDIATE），忙时跳过该整个项目进待检查项
  （TaskBusy 的跨进程互斥兜底），done/failed 正常收尾（测试断言任务行）。
- **库与配置**：library.json 与 config.json 迁移前后字节相同、不改动；
  损坏的应用文件原样保留并成为待检查项（测试覆盖）。
- **顺带修复（测试隔离缺陷）**：`tests/test_registry.py` 两个测试
  （同名隔离、relocate 保留资产）调用 `util.store_dir()` 未重定向 app_dir，
  每次全量跑都会向真实 work/ 漏 UUID 垃圾目录（本机已积一批，本次清理了
  本次运行新漏的 3 个；更早的属用户本机数据未动）。修复后全量跑验证
  work/ 零新增。

code-review（双轴）处理：迁移任务登记（补 spec 的项目任务要求）、启动弹窗
只在有可迁移项目时出现（修"每次启动都弹"）、恢复备份补 UI 入口（设置 →
数据维护）、词汇修正（新增字符串不再用「日志」「游戏目录」「缓存」Avoid
词）、重复代码收敛（`_iter_migratable_jobs`/`_copy_tree_contents`）。

说明与遗留：
- **迁移译文登记为未确认**（来源 migration）：旧格式没有人工确认标记，无法
  区分人工与模型产出，按保守语义与工单 05 的镜像导入同一约定，交用户后续
  确认。已知边缘：「清空译文缓存」会清掉未确认的当前译文——旧数据仍在原
  目录，删除该目录里的 `_migrated.json` 后重启即可重新迁移（模块文档与恢复
  完成提示均已写明恢复路径）。
- `_fail_at` 失败注入参数保留为公开测试接缝：spec Testing Decisions 明确
  要求"故障中断后可恢复"的迁移测试，显式接缝比 monkeypatch 内部函数稳。
- 匹配边界：旧目录名的 `_` 无法还原原字符（A_B 可能来自 A:B），匹配不到
  即 missing 进待检查项，不猜测；目录名仅大小写差异的多个旧目录会先后并入
  同一安装对应的项目，资产冲突进待检查项。
- 检查中心（spec 阶段 2）落地后，review_items 应汇入其中；当前以任务摘要
  日志为载体。
