## Answer

实现(spec「并发与应用(ADR-0005)」;测试 `tests/test_applytxn.py` 11 项 +
合成 e2e 新增工单 07 段):

- **应用事务器**:`core/applytxn.py` ——「应用到游戏」= 暂存生成 → 快速结构
  检查 → 统一替换 → 应用清单/恢复点。暂存区在项目资产目录
  (work/<身份>/apply_staging/,应用结束即删),镜像游戏安装相对结构;
  pipeline 侧 `Project.apply_txn` 先做出现位置同步、旧缓存导入与译文映射
  (数据准备),applytxn 只负责文件事务——两个模块不互相导入。
- **暂存生成**:tl 骨架按 keep_files(当前任务清单识别的文件集)复制进暂存
  区并在副本上回填;人名与关系词显示层(zz_ng_text.rpy)**每次应用都重新
  生成,不受任何开关限制**(此前「应用修改到游戏」不刷新显示层——隐藏例外
  已消除);字体(tl 覆盖脚本 + 中文字体资产)与语言入口受应用设置开关控制。
  fontpatch 拆出 font_override_content / lang_entry_content /
  text_helpers_content 三个内容生成函数供暂存区复用(写入游戏目录的旧入口
  保留,内部走同一生成函数;text_helpers 的物品名译名改从暂存 tl 取,不再
  读游戏目录里上一次应用的旧表)。
- **快速结构检查**:tl 副本与骨架逐行"引号外内容"一致(回填只允许改变引号
  里的内容)、工具生成脚本的 init/translate python 块逐块 compile、无控制
  字符;任何一条不过即中止,游戏目录零改动。
- **统一替换与无半应用**:先为每个受影响文件把替换前字节收进恢复点备份
  (work 目录内),写事务日志(journal),再统一替换(含物理字体替换)。
  异常时按日志回滚;进程崩溃留下的"有日志、无清单"目录在下次应用/停用时
  由 recover_interrupted 回滚——失败/未提交的应用若创建了游戏内字体备份
  目录(fonts_ng_backup)也一并移除,失败的尝试不留任何痕迹。应用清单
  (manifest.json)= 提交点:记录每个文件的动作(新增/修改/移除)、归属
  (译文/字体/语言入口/显示层/旧版遗留)与前后 sha256。tl 下不在任务清单
  里的孤儿文件按移除处理(字节进恢复点,可还原)。
- **恢复点**:work/<身份>/applies/<应用ID>/{manifest.json, backup/<相对路径>}。
  `restore` 按清单精确逆向撤销单次应用(建议从最新开始连续撤销);`diff`
  返回每文件的动作/归属/前后哈希/当前是否仍在该状态;UI 恢复点对话框
  (ApplyPointsDialog)列出全部应用,选中文件看行级差异(difflib,应用前 ←→
  当前),支持还原与停用。还原/停用登记为项目任务(kind=应用),经协调器
  与其他核心数据任务互斥。
- **停用汉化**:`deactivate` 按全部清单从新到旧依次撤销(逐步回到第一次应用
  之前),再清理工具命名空间残留与物理替换字体(游戏内备份还原)。只撤销
  工具管理的文件:玩家的文件、提取骨架、汉化项目及其资产(项目库译文、
  恢复点)原样保留,再次应用即恢复。**zz_ng_dyntrans.rpy(运行时过滤器)
  保留不删**:uipatch 改写过的游戏脚本表达式全部调用其 _ng_t,它是被改写
  脚本的运行时依赖而非汉化显示层。
- **任务摘要**:`run` 返回 {filled, untranslated, dropped, suggestions,
  files_total, files(按归属), fonts_replaced, restore_point};
  `summary_message` 统一格式化(成功、跳过、待检查数量),界面状态栏与
  流程日志共用一份。含原文没有的 [变量] 的译文拒用并计入待检查(绝不进
  游戏)。
- **UI**:第 6 步、「⤵ 应用到游戏(试玩模式)」、编辑页「应用修改到游戏」
  全部走同一事务(`_op_fill`/`_op_finish`,回填幂等、无需重新翻译);设置页
  「仅应用字体」按钮删除(统一应用没有部分应用的例外);新增「🧯 恢复点 /
  停用汉化」入口。`fill_partial` 中间层删除,`_jobs` 的 translate_strings
  回填过滤挪到 `_fillable_files`(纯 strings 文件仍属暂存集,只是不回填,
  不会被统一替换误删)。

code-review(双轴)处理:Spec 轴两个实质缺陷——①每次应用误删
zz_ng_dyntrans.rpy(uipatch 改写脚本的 _ng_t 运行时依赖,删除会让游戏
NameError;应用与停用均改为保留,测试同步修正);②替换阶段回滚后
fonts_ng_backup 残留(失败/未提交的应用若创建了该目录,回滚时一并移除;
新增"字体替换完成后失败"的故障注入测试,全量目录树断言零痕迹)。范围收敛:
「仅应用字体」按钮删除(统一应用无部分例外);恢复点差异视图升级为行级
difflib。Standards 轴:`_op_font_only` 名实不符(随按钮删除)、fill_partial
纯转发(删除)、lang_entry 默认语言名去重(default_lang_name)、停用计数
两处重复(deactivate 返回 files 总数)、摘要格式两处维护(收敛为
applytxn.summary_message 单一来源)、_op_deactivate/_restore_op 补挂
@project_task("应用")、路径拼接收敛 _at 助手。判断性保留:run 的显式关键字
参数(Data Clumps 提示;模块边界是刻意的数据准备/文件事务分离)、恢复点
对话框经主窗口触发操作(Qt 既有模式)。

说明与遗留:
- **外部 tl 变更检测(应用前)属工单 08**:本工单的应用直接以项目库当前译文
  生成暂存区;08 将保存上次应用基线并在应用前对比游戏目录的 tl 变更。
- restore 精确语义是"撤销这一次应用";跳着还原旧恢复点会得到混合状态(界面
  提示从最新开始连续撤销,停用即自动做完整序列)。
- 已提交应用的 fonts_ng_backup 按清单保留(本地安全网,清单注明);停用时由
  restore_fonts 消费。测试对账时排除该目录的树对比仅用于 restore 单次撤销
  的用例。
