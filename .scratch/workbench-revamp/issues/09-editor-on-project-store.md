# 09: 译文编辑页接入项目库

**What to build:** 译文编辑页改为从项目数据库按文本出现位置加载与保存:主列表展示状态、说话人、原文、译文;相同原文的"修改此处"与"替换全部匹配项"成为两个明确动作;人工编辑自动保存为项目草稿并显示保存状态;重新提取后编辑页立即使用最新任务清单,不再出现"保存成功但游戏没有变化"。

**Blocked by:** 05(项目数据库:出现位置与译文记录)、06(单项目单写入任务协调器)

**Status:** resolved

- [x] 相同原文的不同出现位置可分别编辑,互不影响
- [x] "替换全部匹配项"是显式批量操作,执行前展示影响范围
- [x] 编辑自动保存为项目草稿,切页、关窗不丢内容,保存状态可见
- [x] 重新提取后编辑页使用最新任务清单
- [x] 项目任务运行期间的编辑遵守协调器规则,冲突进入待检查

## Answer

实现（ADR-0003、ADR-0004；测试 `tests/test_project_store.py` +6 项、
`tests/test_externaltl.py` +1 项、新增 `tests/test_editor_dialog.py` 4 项离屏
界面逻辑测试 + 合成 e2e 新增工单 09 段）：

- **数据接缝**：`pipeline.editor_rows()` —— 编辑页数据从项目库按文本出现位置
  装配：任务清单**总是从当前提取结果重建**（不走可能过期的 jobs.json 镜像），
  行上联查当前译文（`current_records`：文本/来源/确认位）、待检查计数
  （`review_counts`：候选译文与迁移建议分组计数）、同文出现位置数
  （same_source，批量操作的影响范围）。source 是玩家可见的翻译源
  （ipatch 补丁后），anchor 保留被补丁改写前的 tl 锚点。
- **主列表**：每行一个出现位置，列为 状态/说话人/原文/译文；状态区分
  未翻译/模型/人工（受保护）/待检查（有候选或迁移建议，附计数与成因
  工具提示），状态筛选下拉与关键词搜索可组合。双击任意列打开修改对话框。
- **修改对话框（EditTranslationDialog）**：相同原文的「修改此处」与
  「替换全部 N 处相同原文」是两个明确动作——后者执行前展示影响范围
  （多少处、其中多少处当前译文会被改写、逐处说话人/文件/旧值预览）。
  修改**即时自动保存为项目草稿**（输入停顿 0.7s 落库 + 关窗时补存；
  切页/关窗/崩溃最多丢最后一次停顿内的输入），对话框内与页面底部都有
  「✓ 已保存为项目草稿（未应用到游戏）」状态；关键词批量替换同样先展示
  影响范围（处数/出现数/人工确认条数）再执行。译文与回填同一套占位符
  校验在对话框内实时提示（原文没有的 [变量]/{} 会在应用时被拒用）。
- **待检查处理**：候选译文（重译结果、翻译任务与人工编辑的冲突、被替换的
  旧版本）与迁移建议在对话框内并排比较：采用（`adopt_candidate`，成为人工
  确认的当前译文）或忽略（新增 `dismiss_candidate`，删除该条待比较结果）；
  另有「请求重译」（`request_retranslation`，人工定稿保持回填、结果进候选）。
- **协调器规则**：编辑走项目库受保护写入口（WAL 读写并行），任务运行期间
  浏览与非冲突草稿编辑不冻结（e2e 在登记任务内验证）；编辑页浏览路径构建
  任务清单不再写 jobs.json 派生镜像（`_jobs(persist=False)`），任务运行期间
  不出现第二个镜像写入方。会话内连续编辑经 `rewrite_human_if_current`
  原位改写（不把每个输入停顿堆成版本历史），会话首次写入与被任务接管的
  情形仍走 `set_human_translation` 标准入口（旧值降为候选保留）。
- **e2e 断言**（合成游戏）：出现位置行与任务清单对账、同文两分支独立
  编辑/独立回填、批量替换后两处一并更新、编辑后游戏 tl 在应用前不变
  （保存草稿 ≠ 应用到游戏）、重新提取后清单即时更新（改写文本在列未译、
  旧译文降为迁移建议）、最新清单上的编辑经应用一定落进游戏 tl、冲突进
  待检查→采用/忽略、任务运行期间浏览与编辑照常。
- **顺带修复（工单 08 语义边界，由 09 的编辑→应用流程暴露）**：首次应用前
  （无基线）的检测参照补上 `known_texts`（项目库记录过的全部译文文本，
  `history_texts`）——编辑页保存了草稿还没应用时，游戏 tl 停留在上一个
  工具写入值（仍在项目库版本历史里），不再被误报为外部译文变更；
  真正的外部内容照常被发现（既有 08 测试不受影响，另加 1 项回归测试）。

code-review（双轴）处理：批量写入后不可见行（筛选/截断之外）的状态陈旧
——回执改为更新全部已载入行、只重画可见行；编辑页浏览路径写 jobs.json
——`_jobs` 拆出 persist 参数，浏览路径只读；「崩溃不丢内容」的文档承诺收窄
为实测语义（丢最后一次停顿内的输入）；镜像刷新尾巴与对话框写收尾各自
提取共用方法；会话原位改写判定移入项目库（`rewrite_human_if_current`，
界面不再伸手进库内字段）；`suggestions(oid)` 补范围查询与 candidates 对称。

说明与遗留：
- **修改对话框内的实时占位符校验、忽略候选（dismiss）**超出工单字面清单：
  前者服务「保存成功但游戏没有变化」的另一半成因（坏占位符译文应用时被
  拒用显示英文），后者是「待检查项得到处理」的另一条出口（不忽略则计数
  永不清零）；均为小而直接的服务面，未引入新概念。
- **检查中心的统一呈现属阶段 2**：本票的待检查呈现是编辑页状态列 + 修改
  对话框比较区，汇入检查中心（故事 23）时直接消费 candidates/suggestions，
  数据层无需再动。
- 关键词批量替换沿既有交互（搜索框关键词 → 替换词），按出现位置逐条写入；
  若后续要按「同文分组」再聚合展示，可在编辑页数据上直接加分组视图。
