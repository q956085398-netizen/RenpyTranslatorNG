# 08: 外部 tl 变更检测

**What to build:** 每次应用保存基线;下次应用前检测用户或其他工具在汉化工作台之外对游戏 tl 文件的外部译文变更,提供逐项比较、导入或明确放弃三种处理,绝不静默覆盖。导入的译文保留人工来源标记,受到人工译文保护(ADR-0005)。

**Blocked by:** 07(事务式应用与恢复)

**Status:** resolved

- [x] 应用前自动检测外部译文变更,无变更时不打扰
- [x] 存在外部变更时阻止直接覆盖,提供比较视图
- [x] 可逐项导入,导入结果标记为人工译文来源
- [x] 可显式放弃外部变更并在清单中留痕
- [x] 基线随每次应用自动更新,无需手工维护

## Answer

实现(spec「并发与应用(ADR-0005)」;测试 `tests/test_externaltl.py` 14 项 +
合成 e2e 新增工单 08 段 9 条断言):

- **基线**:`core/externaltl.py` —— 每次应用成功(以及恢复点还原/停用后,
  经 pipeline 包装)扫描 game/tl/<语言>/ 全部 .rpy 存成
  `work/<身份>/tl_baseline.json`:{文件: {sha256, 出现位置 -> 译文+原文锚点}},
  表示"工具最后写进游戏的状态",自动维护。检测参照物是基线而**不是**项目库
  当前译文:用户在工具里改了还没应用的**项目草稿**不算外部变更,不打扰。
  基线与应用清单同目录同性质(可从清单+重扫描推导的文件事务产物),
  项目库仍是译文记录唯一可信来源(ADR-0004 不受影响)。
- **检测**:`detect_changes` 逐文件对账——sha 与基线一致即跳过;再按全部应用
  清单的前后哈希对账工具自身写过的状态(自身应用/恢复点还原/停用/提交点附近
  崩溃都不误报,工具创建过的文件缺席也不报);最后按出现位置逐条比较产出
  变更项:modified(改写)/added(补译)/removed(删行)/unmanaged(不在任务
  清单)/structure(结构错位)/removed_file/untracked(文件级)。**首次应用前**
  (无基线)以"翻译/回填步骤实际写入游戏 tl 的内容"(pipeline 按项目库展开,
  `_draft_expected`)为参照:游戏自带或其它工具已有的译文在第一次应用前也能
  被发现并导入,不被静默覆盖。
- **阻止与处理**:`pipeline._resolve_external_changes` 在 `apply_txn` 里于
  应用事务之前执行——无变更零打扰(确认通道不触发);有变更而无确认通道
  (脚本调用)抛 `ExternalChangesError` 阻止应用;确认协议走 Worker 既有
  confirm 通道("EXTTL:"+JSON)。逐项决策:导入 = `set_human_translation`
  (人工来源+确认位,受 ADR-0003 人工译文保护,模型重译只进候选)、放弃 =
  明确允许本次应用覆盖;有未处理项即中止;取消中止应用,游戏目录保持现状。
- **留痕**:应用清单 `external_changes` = {detected/imported/discarded 计数
  + items 逐项明细(哪个出现位置/文件被导入或放弃)},任务摘要带计数。
- **防错位导入**:外部改写注释锚点、或在块内插删行使位置配对错位的
  (译文序列相对基线旋转),整个文件降为 structure 项只提供放弃——绝不把
  译文安到错误的出现位置上。导入含原文没有 [变量] 的外部译文时,确认视图
  预先标注"本次应用仍会拒用该行(显示英文)",工单 07 的运行时安全不变量
  不破。
- **UI**:`ExternalChangesDialog` 比较视图(文件/原文/工具译文←→游戏目录外部
  修改/变更类型,行级差异预览,全部导入/全部放弃/继续应用/取消);第 6 步、
  试玩模式、编辑页「应用修改到游戏」与全流程统一传入确认通道;全流程对外部
  变更加入"已取消"的准确回报;停用/还原改走 pipeline 包装刷新基线。
- **扫描器**:`tlgen.scan_translations`(公开,与 `fill_translations` 同一套
  块结构与位置配对规则,返回译文+锚点)——写入与检测读回按同一规则对齐,
  不再各自维护解析逻辑。

code-review(双轴)处理:Spec 轴四个实质缺陷——①首次应用前无检测(用
_draft_expected 参照补上,e2e 07/08 段的"翻译已回填再首次应用"回归通过);
②放弃留痕只有计数(清单补 items 逐项明细);③全流程吞掉外部变更中止结果
(改为准确回报"已在中止,游戏目录未改动");④结构错位可能导入错误 (key,译文)
对(锚点对账+序列旋转启发式,错位文件整体仅可放弃)。判断性保留:放弃过的
外部内容以相同字节再现不再重新打扰(视为对那份内容的决定)、工具创建文件的
外部删除不报(生成产物,每次应用重建)——均在模块 docstring 记录取舍。
Standards 轴:扫描逻辑挪进 tlgen 公开函数消除对私有实现的伸手;死常量删除;
`ExternalChangesError.items` 用于错误消息;基线刷新收敛 `_refresh_tl_baseline`;
`(work, game_base, language)` 三元组不再重复展开。

说明与遗留:
- 外部改写注释锚点后选"放弃":应用会在当前(被外部改过的)游戏 tl 副本上
  回填,注释残留会保留——暂存源取自游戏 tl 是工单 07 既有语义,结构修复
  属后续工单(重提取可重建骨架)。
- 检查中心(工单 10/阶段 2)可消费 `detect_changes` 的结构化结果作为
  "外部改动"健康检查项;本票只在应用路径上强制拦截。
